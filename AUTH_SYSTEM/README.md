# AUTH_SYSTEM — Skrip DDL RBAC Multi-Tenant (untuk review)

Paket skrip untuk membangun skema RBAC terpisah (`AUTH_SYSTEM`) tanpa menyentuh
tabel transaksional yang sudah ada (`DATA_ECOMMERS`, `FASHION_SALES`,
`DASHBOARDS`, `DASHBOARD_WIDGETS`).

## Akun contoh (seed) — 4 akun

| Username | Peran | Kementerian | OTP |
|----------|-------|-------------|-----|
| `admin.kemenkeu` | Admin | KEMENKEU | aktif (IS_TOTP_ENABLED = 1) |
| `user.kemenkeu` | User | KEMENKEU | nonaktif |
| `admin.fashion` | Admin | FASHION | aktif (IS_TOTP_ENABLED = 1) |
| `user.fashion` | User | FASHION | nonaktif |

Password asli TIDAK disimpan di skrip — hanya kolom `PASSWORD_HASH`.
Ganti placeholder hash dengan hash bcrypt/argon2 dari backend sebelum dijalankan.

## Apa yang disimpan di database?

- **Username** → kolom `MASTER_USER.USERNAME` (unik). ✅ disimpan
- **Password** → kolom `MASTER_USER.PASSWORD_HASH` berupa **hash**, bukan teks
  asli. ✅ disimpan sebagai hash; verifikasi (bcrypt.compare) dilakukan di backend.
- **OTP (TOTP)** → kolom `MASTER_USER.TOTP_SECRET` + `IS_TOTP_ENABLED`.
  Yang disimpan adalah **secret TOTP** (bukan kode 6 digit). Kode OTP bersifat
  sementara dan diverifikasi di backend, tidak pernah disimpan.

## Prinsip desain

- **Skema terpisah.** RBAC tidak bercampur dengan data transaksional.
- **Tanpa migrasi.** Tidak ada `ALTER`/`DROP` ke tabel yang sudah ada.
- **PK identity.** Setiap tabel pakai `ID NUMBER GENERATED BY DEFAULT AS IDENTITY`.
- **Natural key unik.** `CODE`/`USERNAME` diberi `UNIQUE` agar valid jadi target FK.
- **Soft delete + audit.** Kolom `IS_ACTIVE`/`IS_DELETED` (CHECK 0/1) dan kolom audit.
- **Isolasi tenant.** Query menu selalu memfilter `MINISTRY_CODE` user.
- **Password aman.** Hanya `PASSWORD_HASH` yang disimpan; verifikasi di backend.
  Password mentah tidak ditulis di skrip mana pun.
- **OTP opsi ringan.** TOTP lewat 2 kolom di `MASTER_USER` (tanpa tabel tambahan).

## Yang sengaja TIDAK dilakukan

- Tidak mengubah PK `DATA_ECOMMERS`/`FASHION_SALES` menjadi IDENTITY (berisiko
  pada tabel sumber yang sudah berisi data).
- Tidak memindahkan `DASHBOARDS`/`DASHBOARD_WIDGETS` ke skema baru (akan memutus
  fitur dashboard yang sudah berjalan).
- Tidak memberi hak `CREATE USER`/DBA ke akun aplikasi.
